# 大脱獄：ゲームフロー・看守監視・看守視界・フィールド構造

Unity `6000.6.6f1` / C# の既存プロジェクトです。DEV-TURN-001のゲームフロー、SYS-GUARD-001 v1.2の監視山札・公開履歴、SYS-VISION-001 v1.0の看守視界に、SYS-FIELD-001 v1.0のデータ駆動フィールドを接続しています。今回のブランチは `codex/sys-field-001-v1-0` です。`origin/plan-main` を基点とし、依存する監視・視界のコミットを含みます。

監視山札の確率・構成・履歴管理と純粋な視界の式は維持しています。形状・初期柵・初期看守は選択ステージから取得します。本番スキルカード・山札構成は未提供のため、ステージ01を開始しても既定シーンではカード設定待ちになります。製品版の対局全体やSYS-PRISONER-001が実装完了した状態ではありません。

## 起動・設定

1. Unity Hub から Unity `6000.6.6f1` で開きます。
2. `Assets/Scenes/Daidatsugoku.unity` を開き、Play を実行します。
3. ステージ選択画面でステージを選び、「このステージで開始」を押します。盤面とUGUIは実行時に生成し、カメラを選択ステージの寸法へ調整します。

シーン作成メニューは `Tools > Daidatsugoku > Create Prototype Scene` です。既存シーンを上書きしないため、通常は作成済みシーンを開きます。Unity の Build Profiles から同シーンを対象にビルドします。

ステージアセットの初回生成は、Playを停止して `Tools > Daidatsugoku > Configure Field Stages` を実行します。`FieldStageAssetBuilder.ConfigureProject()` は既存ステージアセットを上書きしません。旧メニュー `Configure Prototype Guard Vision` も同じ設定処理を呼びます。

設定項目は以下のとおりです。

| 設定先 | 内容 |
|---|---|
| `GameManager.playerCount` | 2～4人、既定3人。開始時にランダムな固定手番順を決定。 |
| `GameManager.skillCards` | `SkillCardDefinition` 派生型の本番カードアセット。枚数・条件・効果はカード仕様に従う。 |
| `GuardSystem.monitoringSource` | 任意の `GuardCardSource` 派生型による上書き。未指定なら v1.2 の標準監視山札を使用し、本番監視用アセットの設定は不要。成功した最初の監視以降の変更は次回 `ResetDeck()` から適用。 |
| `Assets/Resources/FieldStages/*.asset` | `FieldStageDefinition`。ID・名称・寸法・行範囲・初期看守・初期柵を保持。起動時に自動列挙し、構造と開始可否を検証。 |
| `GameManager.CollisionResolver` | `IPrisonerCollisionResolver`。占有先への移動を囚人システムへ委譲。未接続時は理由を表示して停止。 |

## 看守監視と公開履歴

- 監視山札は30枚。生成ごとに監視率20・30・40・50・60・70・80%から独立に1/7で選びます。同じ率が連続することもあります。
- 見とる枚数は順に6・9・12・15・18・21・24枚です。残りを見とらんとして、生成時に Fisher-Yates で一度だけシャッフルします。消費中には再シャッフルも独立した結果抽選もしません。
- 看守ターンに1枚消費し、31回目の判定直前に新しい山札を生成します。30枚目の結果・履歴は保持し、新しい山札から余分なカードを消費しません。
- `TryDrawMonitoring(round, ...)` へ同じラウンドを再要求すると、確定済みの結果を返します。山札消費と履歴追加は一度だけです。初期化では履歴と判定済みラウンドもリセットします。
- `PublicHistory` が返す公開値は `GuardHistoryEntry.SequenceId`、`DeckId`、`CardIndex`、`Result` のみです。監視率・山札配列・残りの内訳・次回結果はUIに渡しません。
- 画面右上に常時表示される「監視履歴」から、全画面の半透明オーバーレイを開閉できます。全件を時系列で表示し、山札番号の区切りと通算番号・山札内番号を付け、長い履歴は縦にスクロールします。
- 仮デザインは黒70%の背景、赤 `#DC2626` の見とる／緑 `#16A34A` の見とらん、白太字の縦書きです。装飾・ブラーはありません。`GuardHistoryTheme` で色・寸法・余白・文字サイズを変更でき、判定ロジックには影響しません。
- 履歴表示中は履歴画面への入力だけを受け付けます。開閉によるドロー・ターン進行・時間停止は行いません。オンライン／オフラインの進行制御は本仕様では未確定です。

## 看守視界と監視への接続

- 盤面・囚人・柵は左下原点のXYです。純視界ロジックの `VisionCell(Row, Column)` は上始まりの行座標を維持し、`GridManager.ToVisionCell()` で `Row=Height-1-Y, Column=X` へ一度だけ変換します。`TryGetVisionCell()` で逆変換し、前面柵・対象囚人・デバッグも同じ変換を使います。
- `GuardPosition` は基準列とTOP/BOTTOMを保持します。初期値はフィールドから読み、ランダム配置しません。`GuardVisionSystem.Flip()` は方向と常時表示だけを切り替え、監視抽選・発見処理を起動しません。
- `GuardVisionCalculator` はUIやUnityに依存しません。距離 `d` に対して左右へ `(d - 1) / 3 + 1` 列広げ、盤面外を切り捨てます。TOPの距離は `row + 1`、BOTTOMは `rowCount - row` です。
- 基本視界を先に求め、その中の柵だけを抽出します。各列で看守に最も近い有効な柵を採用し、TOPは柵のマスを含む下側、BOTTOMは柵のマスを含まない上側を遮蔽します。視界の計算結果は重複のない集合です。
- 看守ターンは、監視カード抽選 → 許可された割り込みの解決 → 最終結果確定 → 視界スナップショット → 全発見対象の通知、の順です。「見とらん」または監視無効の場合は視界計算・発見通知を行いません。
- `IGuardVisionSnapshotService` により発見判定1回につき最新の盤面・看守・柵から1つの視界スナップショットを作ります。通常のプレイヤーターンでは毎フレーム計算しません。
- `GuardSystem.PrisonersDiscovered` は全対象を変更不可のリストで一括通知します。囚人状態更新は `IGuardPrisonerService`／`IGuardPrisonerBatchService` へ委譲し、既定アダプターは既存 `Prisoner.Capture()` を使用します。除外された囚人は再配置できず、脱獄人数にも加算しません。

監視への割り込みは、カード側が `CanInvalidateGuardMonitoring` を明示し、`CanPlay()` の条件と外部 `TurnFlowPolicy` の対応計画を満たす場合だけ対象にします。この印だけで使用タイミングや優先権は定義されません。新しい本番カードや未確定の割り込みルールは追加していません。旧所有者別の看守対応コードは互換用に残し、標準フローからは呼びません。

### SYS-FIELD-001のステージデータ

各 `FieldRow(Y, StartX, EndX)` の両端を含む連続範囲だけにマスが存在します。`FieldStageDefinition.ToStage()` は元コレクションをコピーした変更不可の `FieldStage` を返します。有効マス・各行のスタート／出口・禁止位置・合計マス数は行データから算出し、アセットに重複保存しません。

| ID | 名称 | 寸法 | マス数 | 初期柵 |
|---|---|---|---:|---|
| 01 | オリジナル | 7列×5行 | 25 | 指定5本・確定 |
| 02 | ロングフィールド | 8列×5行 | 34 | 未確定・開始不可 |
| 03 | アシンメトリーフィールド | 7列×6行 | 31 | 未確定・開始不可 |
| 04 | ピラミッドフィールド | 7列×7行 | 35 | 未確定・開始不可 |
| 05 | 双頭の監獄 | 9列×9行 | 55 | 未確定・開始不可 |

ステージ01の元資料は行定義の合計24マスと記載総数25マスが不一致でした。ユーザー承認によりY=2の終了Xを4から5へ変更し、25マスと列ごとのマス数 `2・4・5・5・5・3・1` に一致させています。

`initialFencesDefined=false` は未確定を表し、空配列でも正式な「初期柵なし」とは扱いません。構造参照は可能ですが、`TryValidateForPlay()` が開始を拒否します。正式に柵なしと確定した場合は `true` と空配列を明示します。アセットの `sourceIssue` に確認待ち理由がある場合も開始を拒否します。

新規ステージは `Create > Daidatsugoku > Field Stage` で作成して `Resources/FieldStages` に追加します。ID分岐や描画コードの追加は不要です。構造検証は最小5行・3列、必須値、行の欠落・重複・逆順範囲・範囲外、TOP以外の初期看守、正面3列の欠落、初期柵の非実在・重複・禁止位置を拒否します。カタログに重複IDや不正ステージがある場合も開始を拒否し、自動修正しません。

`GuardVisionSystem` は `GridManager.Field` を唯一の実行時フィールド情報源とし、視界結果から非実在セルを除外します。旧 `GuardVisionFieldDefinition` と `PrototypeGuardVisionField.asset` は既存ファイルとして残しますが、実行時には使用しません。

`GuardVisionDebugDisplay` のInspectorで `Show Vision` を有効にし、コンポーネントのコンテキストメニュー `Refresh Vision Debug Snapshot` を実行して、SceneビューのGizmosを確認します。看守の位置・前面柵・最終視界を表示します。反転・柵変更後は明示的に再実行してください。

## 進行と操作

初期手札0枚、盤上囚人0人、累計脱獄0人、ラウンド1で初期化します。各プレイヤーは既存どおり未配置囚人3人を持ち、初期柵は選択ステージから取得します。最初のターン開始時からドローするため、操作可能時点の手札はドロー後の枚数です。

- 各ターンに「囚人配置」「囚人移動」「柵設置」「柵破壊」の可能な行動を1回実行します。
- 可能な通常行動がある間は終了・パス不可。宣言後に妨害されても消費します。
- 通常行動後は自動終了しません。カードを使用し、未解決処理がなくなってから「ターン終了」を押します。
- 通常行動不能でカード使用可能ならカードまたはパスを選択。両方不能ならドローと効果解決後に自動パスします。
- 「手札を開く」で所有者とページを選択します。使用可否は各カードの発動条件に従います。
- 超過時は新しく引いたカードも含め5枚以下になるまで任意に捨てます。対応中は対応者のカード選択・パスを表示します。
- 全員終了後に看守ターンへ進み、監視への許可された割り込みを解決してから視界と全発見対象を確定します。すべて完了後に次ラウンドへ進みます。
- チェーン解決後に脱獄を最終確定し、累計3人で即時勝利。勝利後は以後の進行を停止します。

## フィールドの配置・境界と囚人システムの接続

- 各行の左端がスタート、右端が出口です。全体のX=0や最右列に固定しません。通常配置は空きスタートだけに許可し、配置時の喧嘩は起こしません。
- `GridManager.OccupantAt()` は現在の囚人状態を参照します。1マスの囚人は最大1人で、柵は占有枠を消費しません。柵のある空きスタートにも配置できます。
- `FieldStage.ClassifyMove()` は囚人側で方向・距離を検証した後の1ステップを分類します。移動元の行の右端を越える右移動を先に脱獄とし、斜め右で上下の外形外へ出る場合も優先します。それ以外の非実在着地は不可です。
- `ClassifyPush()` は対象行の左端を越える押し出しを `ReturnToUnplaced`、右端を越える押し出しを `Escape` として返します。確率・連鎖・状態変更は囚人システムへ委譲します。
- 柵は対応マスの上端に置き、`FenceBoundary.Column=X, Line=Y, Vertical=false` で管理します。縦辺は対象外です。初期柵も破壊可能です。
- 初期看守はステージ指定列・TOPです。基準列±1の各列の最上段マスを禁止位置にし、反転しても変更しません。
- 最大寸法はゲームルールとして固定しません。座標は `Int32`、合計は `Int64`、`IReadOnlyCollection.Count` は.NETの `Int32` 表現上限という技術的制約があります。

既存通常操作の右・上・下の隣接移動と脱獄人数ベースの勝利処理を維持しています。SYS-PRISONER-001の実装前確認・承認が未完了のため、6種類・6人、タイプ別移動、能力、喧嘩抽選・連鎖、左押し出しの未配置化、ポイント勝利と即時中断を今回追加していません。境界分類APIを囚人側へ接続する必要があります。

占有先への移動は `IPrisonerCollisionResolver.TryResolve()` に委譲します。未接続時は同居させず仕様待機にし、独自の喧嘩確率や結果を決めません。低レベルの `Prisoner.Deploy()`／`MoveTo()` も非実在マス・同居を防ぎます。

## 未確定時の停止と再確認

スキル山札と使用済みがともに空の場合はドローを省略せず理由を表示して停止します。必要な対応計画・複数所有者順がない場合、明示的な監視上書きが結果を供給できない場合も同様です。監視供給元の未指定は停止理由ではなく、標準山札を使用します。「設定を再確認」は再試行可能な待機について設定を再評価します。

不正・未確定のステージは盤面生成前に拒否します。未確定ステージの再開始操作から旧盤面を進行させたり、旧開始APIでステージ選択を迂回したりすることも防ぎます。設定を修正して、表示される再確認・初期化手順に従ってください。

効果解決中に新しい即時発動が発生した場合や、効果内で山札と使用済みがともに空になった場合、未定義の優先順位を決めて残りの解決を進めません。途中適用状態を保持して停止します。**途中状態からの再開は未実装**です。関連仕様と設定を修正後、対局を再開始する必要があります。

## 検証

Play 中に `Tools > Daidatsugoku > Run Play Mode Checks` を実行します。対局を初期化し、明示的なテスト用カード・監視供給元・対応方針で検証して、設定を復元します。セーブ・通信・同期は既存 main に存在しません。

Editor専用フィールドでの検証は正式ステージの代用として出荷しません。実SceneビューのGizmos手操作、本番の個別カードでの通し対局、オンラインは未検証です。
