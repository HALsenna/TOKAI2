# 大脱獄：DEV-TURN-001 ゲームフロー基盤

Unity `6000.6.6f1` / C# の既存プロジェクトです。`main` の `7036401` を起点に、SYS-TURN-001 v1.0 の確定済みフローを新規設計しています。PR #5 / PR #7 のコード・設計を流用せず、別ブランチ `codex/dev-turn-001-rebuild` で実装しています。

本番スキルカードと SYS-GUARD-001 v1.1 に適合する監視カード供給元は未提供です。既存シーンをそのまま再生すると「仕様・設定の確認待ち」で停止します。独自カードや固定監視率を補って進行することはありません。現時点は**ゲームフロー基盤の部分実装**です。

## 起動・設定

1. Unity Hub から Unity `6000.6.6f1` で開きます。
2. `Assets/Scenes/Daidatsugoku.unity` を開き、Play を実行します。
3. 盤面と UGUI は実行時に生成します。既存シーン・カメラ・クリック入力の参照は維持します。

シーン作成メニューは `Tools > Daidatsugoku > Create Prototype Scene` です。既存シーンを上書きしないため、通常は作成済みシーンを開きます。Unity の Build Profiles から同シーンを対象にビルドします。

仕様提供後、以下の実装と参照設定が必要です。

| 設定先 | 内容 |
|---|---|
| `GameManager.playerCount` | 2～4人、既定3人。開始時にランダムな固定手番順を決定。 |
| `GameManager.skillCards` | `SkillCardDefinition` 派生型の本番カードアセット。枚数・条件・効果はカード仕様に従う。 |
| `GuardSystem.monitoringSource` | `GuardCardSource` 派生型。監視生成・抽選・履歴は SYS-GUARD-001 v1.1 の専用実装が担当。 |
| `GameManager.flowPolicy` | `TurnFlowPolicy` 派生型。初回対応権、対象なし/複数対象、複数所有者順などの確定仕様を渡す。 |
| `GameManager.actionRules` | `NormalActionRules` 派生型。未指定時は `PrototypeActionQuery` が既存盤面ルールへ問い合わせる。 |

抽象型だけでは本番設定は完了しません。Editor 検証のカード・監視・優先順位フィクスチャーは本番アセットの代用にしません。

## 進行と操作

初期手札0枚、盤上囚人0人、累計脱獄0人、ラウンド1で初期化します。各プレイヤーは既存どおり未配置囚人3人を持ち、初期柵は既存配置を使用します。最初のターン開始時からドローするため、操作可能時点の手札はドロー後の枚数です。

- 各ターンに「囚人配置」「囚人移動」「柵設置」「柵破壊」の可能な行動を1回実行します。
- 可能な通常行動がある間は終了・パス不可。宣言後に妨害されても消費します。
- 通常行動後は自動終了しません。カードを使用し、未解決処理がなくなってから「ターン終了」を押します。
- 通常行動不能でカード使用可能ならカードまたはパスを選択。両方不能ならドローと効果解決後に自動パスします。
- 「手札を開く」で所有者とページを選択します。使用可否は各カードの発動条件に従います。
- 超過時は新しく引いたカードも含め5枚以下になるまで任意に捨てます。対応中は対応者のカード選択・パスを表示します。
- 全員終了後に看守ターンへ進み、結果と対象確定後に所有者別の対応機会を設けます。すべて完了後に次ラウンドへ進みます。
- チェーン解決後に脱獄を最終確定し、累計3人で即時勝利。勝利後は以後の進行を停止します。

## main から維持する個別ルール

今回の指示書から盤面・移動・視界を再定義していません。

- 段差盤面は A=3、B=4、C=5、D=6、E=7マス、計25マス。左オフセットは A=2、B=1、C=1、D=0、E=0。
- 囚人は既存の任意マスへ配置でき、同居も可能。
- 右・上・下の既存隣接判定を使用し、段差外・斜め移動は不可。
- A2/B3/C4/D5/E6から既存の「右へ／脱獄」で脱獄。
- 柵は共有境界へ配置。初期5本は B0・C0・C2・D4・E2 の北側境界。初期柵も破壊可能。
- 柵・囚人による移動妨害は追加せず、横向き柵より下の同じ縦筋を保護する既存視界を使用。
- 捕獲・復帰の新ルールは追加せず、既存 `Prisoner` の捕獲処理を使用。

main の強制配置、行動直後の自動ターン終了、全員勝利不能時の「勝者なし終了」は、今回の確定済みフローに従って除去しました。

## クラスの責務

| ファイル | 責務 |
|---|---|
| `GameManager.cs` | 状態・手番・ラウンド、宣言/実行の分離、カード/看守連携、最終脱獄と勝利確定。 |
| `TurnContracts.cs` | フェーズ、宣言/発動/捕獲イベント、外部指定の対応計画。 |
| `NormalActionRules.cs` | 通常行動の問い合わせ口と既存盤面用 `PrototypeActionQuery`。 |
| `SkillCardDefinition.cs` | カード表示・即時属性・対象・発動条件・効果の拡張口。 |
| `SkillCardPile.cs` | 山札・使用済み・再シャッフル。手札は回収しない。 |
| `ResponseChain.cs` | 外部指定2人の交互対応・連続パス・LIFO。初回対応者は内部で決めない。 |
| `TurnFlowPolicy.cs` | 未確定の参加者・初回対応・複数所有者順を外部仕様から渡す。 |
| `GuardCardSource.cs` / `GuardSystem.cs` | 本番監視供給元と既存視界の対象列挙。旧 `DrawCard` は互換用で、新フローは使用しない。 |
| `GameHud.cs` | 既存 UGUI の行動・終了・手札・超過破棄・対応・待機・結果表示。 |
| `GridManager.cs` / `Prisoner.cs` | 既存の盤面・共有柵・囚人状態・視界。今回の個別ルール変更対象外。 |
| `GridCell.cs` / `FenceClick.cs` / `FenceBoundary.cs` | 既存クリック入力と共有境界。 |

`SkillCardDefinition.Resolve` のイベントは各カード自身の `SkillActivation` です。対応対象を `Parent` に保持し、元の通常行動・捕獲イベントまでたどれます。取消済み発動は効果を実行せず使用済みへ移します。

## 未確定時の停止と再確認

山札と使用済みがともに空の場合はドローを省略せず理由を表示して停止します。監視供給元がない場合、必要な対応計画・複数所有者順がない場合も同様です。「設定を再確認」は再試行可能な待機について設定を再評価します。

効果解決中に新しい即時発動が発生した場合や、効果内で山札と使用済みがともに空になった場合、未定義の優先順位を決めて残りの解決を進めません。途中適用状態を保持して停止します。**途中状態からの再開は未実装**です。関連仕様と設定を修正後、対局を再開始する必要があります。

## 検証

Play 中に `Tools > Daidatsugoku > Run Play Mode Checks` を実行します。対局を初期化し、明示的なテスト用カード・監視供給元・対応方針で検証して、設定を復元します。セーブ・通信・同期は既存 main に存在しません。

Unity実シーンで206検証成功。Windows64 Developmentビルド成功（エラー0・警告510）、Playerのグラフィック有効/ヘッドレス起動確認済み。盤面シェーダーの除外による起動例外はシーンの明示参照で修正しました。詳細な結果、全変更ファイル・未実装項目・確認事項は `Tools/DEV-TURN-001-report.md` を参照してください。
