# 大脱獄プロトタイプ — SYS-TURN-001 v1.0

`Assets/Scenes/Daidatsugoku.unity` を開いて Play。
盤面・UIは実行時に生成します。既存の画面配置・色・ボタン座標・カメラは維持しています。

## 操作

- GameManagerのInspectorの `Player Count` で2〜4人を設定（既定3人）。
- ゲーム開始時に手番順をシャッフルし、その対局の全ラウンドで固定します。
- 初期手札0枚、盤上の囚人0人、各プレイヤーの未配置の駒3人、初期柵5本。
- 各ターン開始時にスキルカードを1枚引きます。通常行動は配置・移動・柵設置・柵破壊から1回。
- 空いているSTARTに駒を配置。移動は空いている右・上・下の隣接マスへ。他の囚人と同居できません。
- 盤上に駒がなくても柵操作を選べます。配置の強制はありません。
- 通常行動後も自動交代しません。既存の「右へ／脱獄 →」ボタンが「ターン終了」に切り替わります。
- 通常行動ができる間は終了不可。行動不能なら使用可能カードがあれば任意パス、なければ自動パス。
- 「選択中」の見出しをクリックすると、既存のボタン枠を手札表示に切り替えます。
  最初の4枠でカード使用／超過カード破棄、5枠目で次ページ・対応パス・通常行動へ戻る・ターン終了。
  5枚目以降も次ページで選択できます。手札超過・チェーン時は手札表示を強制します。
- 交代確認後に次プレイヤーがドロー。全員の終了後、看守カードを1枚引きます。
- 「見とる」の捕獲確定前に対象所有者ごとのカード対応を待ちます。「見とらん」は捕獲しません。
- 各列右端から「右へ／脱獄」で脱獄。3人目の成功がチェーン後に確定した瞬間、残りの手番・看守を止めて結果表示。
- Restartで盤面、駒、手札、両山札、成功数、チェーンを初期化し、新しい手番順を決定します。

## 実装と専用仕様の接続点

| クラス | 役割 |
|---|---|
| GameManager | 手番、ラウンド、通常行動宣言、チェーン、パス、勝利、看守進行 |
| SkillDeck | シャッフル、ドロー、使用済み回収（手札は回収しない） |
| SkillCard | 個別カードの `Immediate`、`TargetPlayer`、`CanPlay`、`Resolve` を定義する抽象アセット |
| FlowContext | 元イベント、現在の発動契機、行動者・対象、囚人、移動先、柵境界、捕獲対象、無効フラグ |
| FlowRules | 行動禁止、配置／移動制約、設置可否・柵保護を専用仕様や継続効果で判定する抽象アセット |
| GridManager | 既存の段差25マス、隣接判定、共有境界、初期柵、視界遮蔽 |
| GuardSystem | 看守山札、監視結果、所有者別対象列挙 |
| GameHud | 既存UGUIの表示・操作をゲーム状態へ接続 |

具体的な `SkillCard` アセットを GameManager の `Skill Cards` に枚数分登録します。
即時カードは手札を経由せず強制解決し使用済みへ。通常カードは手札へ。
`CanPlay` は必ず現在の発動条件を検査します。手札の存在だけではパスを止めません。
ターン中のカード使用は通常行動を消費しません。効果解決後に行動可否を再判定します。

通常行動は実行可能な対象に宣言した時点で消費扱いに固定し、対応機会の後で適用します。
無効化は `FlowContext.Cancelled` を設定します。解決時に移動先占有や柵保護なども再検査します。
失敗しても行動を取り直せません。

対象のあるカードは使用者と対象者だけが交互に対応し、2回連続のパスで締め切り、LIFOで解決します。
通常行動への最初の対応候補は固定手番順で巡回し、最初のカード使用で2人に固定します。
カードが積まれると `Event` は `SkillCard` になり、`OriginalEvent` は元の行動／看守イベントを保持します。
`LastChainCard` / `LastChainOwner` から直前の発動を検査できます。
解決後に同じ元イベントへ第三者の割り込み窓を開き直しません。
カードから脱獄成功を確定する場合も `ConfirmEscape` を使用し、解決中の勝利はチェーン終了まで保留します。

## 未確定依存と暫定方針

SYS-TURN-001の未確定事項を個別ルールとして確定しないため、以下を明示的に残しています。

- **個別カードの種類・枚数・効果は未登録。** 本番カードを捏造せず、既定のスキル山札は空です。
  両置き場が空ならドローのみスキップして進行。これは仕様未確定のための暫定フォールバックです。
- **SYS-GUARD-001 v1.1本文がリポジトリにないため、抽選確率・履歴の準拠は未完了。**
  初期山札は従来の全監視8枚を保持。`GuardSystem.initialDeck` に監視／非監視を登録可能ですが、
  専用仕様の抽選・履歴管理を代替するものではありません。
- 看守の複数所有者への対応順は暫定で固定手番順。各所有者の捕獲対象をまとめた個別イベントで対応し、
  所有者がパスしてから捕獲を確定します。救出カード使用後も明示パスでその窓を閉じます。
- 対象なし／複数対象カードは暫定で追加チェーンを開かず単独解決。カード解決中の再入割り込みは受け付けません。
- 効果で複数枚引いた場合も上限を超えた所有者が任意に捨てるまで操作をロックします。
  複数の超過所有者は暫定で固定手番順。解決済みのカード効果や元行動を巻き戻しません。
- 囚人総数3人、復活なし、右／上下隣接移動、各行左端のSTART、各行右端の脱獄、
  初期柵B0/C0/C2/D4/E2北辺は既存盤面仕様を保持。スタート位置の正式確定はフィールド仕様待ち。
  柵は移動を妨げず、横柵より下の同じ縦筋を視界から保護します。
- 従来の「全員が勝利不能なら勝者なし終了」は廃止。捕獲後に勝利不能になる対局の救済は囚人仕様待ち。
- 同時脱獄の複数勝者判定は暫定で固定手番順。切断・時間切れ等のオンライン処理は対象外。

## 検証

Play中に `Tools > Daidatsugoku > Run Play Mode Checks`。
実シーンで2〜4人、初期化、固定ランダム順、ラウンド、配置・占有・段差移動、通常行動の1回制限、
明示終了、即時／通常ドロー、手札上限の任意選択、使用済み再生成、行動不能パスと効果後の再判定、
2人チェーン、連続パス・リセット・LIFO・第三者拒否、行動無効、看守所有者別救出と非監視、
脱獄チェーンと即時勝利、結果入力ロック、HUDボタン、リトライを検査します。
個別カード・ルールはEditor内のテスト専用アセットで検証し、本番デッキには追加しません。
終了時にはInspector設定と初期対局を復元します。
