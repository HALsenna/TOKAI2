# DEV-TURN-001 実装報告

## 調査と実装方針

Unity 6000.6.6f1 / C#。`Assets/Scripts/Daidatsugoku` の既存クラス、
`Assets/Scenes/Daidatsugoku.unity`、実行時生成UGUI、Editor実行検査を再利用する。
起動はゲームシーンを開いてPlay。ビルドはBuild ProfilesからWindowsを選択してBuild。
テストはPlay中に `Tools > Daidatsugoku > Run Play Mode Checks`。
既存のnamespace、SerializeField、PascalCase公開API、camelCase内部フィールド、既存アセット名を維持する。
通信・同期・セーブは本フローに存在しない。個別カードアセット、監視履歴画面、専用の結果シーンはない。
勝利表示・手札・パス・チェーン対応・通常行動UIは既存GameHud内に存在する。

調査時点で手番・カード・チェーン・看守連携の基盤はPR #5のブランチに実装済み。
今回の変更は専用ブランチと別PRに分離し、PR #5を更新しない。
PRの取り込み先は `codex/sys-turn-001-flow` とし、今回の差分のみを提示する。
作業前からあるPackagesの変更は含めない。

変更前に報告した仕様との矛盾は、両山札空でのドロースキップ、対象なしカードの単独解決、
初回チェーン対応者と複数看守対応順の固定、監視率が固定された既定山札。
SYS-GUARD-001 v1.1本文・本番カード仕様はリポジトリ内にない。
これらの暫定処理の変更はユーザーへの確認待ちとし、新しい未確定ルールを追加していない。

実装順序：既存構成と差分調査 → 確定済みルールの不備修正 → HUD・ビルド設定接続
→ 実シーン回帰検査 → ビルド → 別PR。シーン・アセットの移動や既存データの初期化は行わない。
