# SYS-GUARD-001 v1.2 実装報告

対象：ユーザー提供の「看守監視システム仕様書 Version 1.2（実装向け整理版）」。作業ブランチ：`codex/sys-guard-001-v1-2`、取り込み先：`plan-main`。

## 実装範囲

監視山札を30枚へ統一し、生成ごとに20・30・40・50・60・70・80%を各1/7で独立に選びます。見とる6・9・12・15・18・21・24枚と残りの見とらんを生成し、Fisher-Yatesで生成時に一度だけシャッフルします。消費中の再シャッフルや、判定ごとの独立した結果抽選は行いません。31回目の判定直前に再生成します。

`GuardSystem` は監視ラウンド単位で結果を確定し、同ラウンドの再要求では山札消費・履歴追加を繰り返しません。公開履歴は `SequenceId`、`DeckId`、`CardIndex`、`Result` の変更不可データだけを返し、山札切り替え後も過去履歴を保持します。新規対局の初期化では履歴を消去します。

`GuardCardSource` は任意の上書き用です。未指定なら標準の監視山札を使用し、監視用アセットの設定は不要です。成功した最初の監視以降の供給元設定変更は、次回 `ResetDeck()` まで保留します。

履歴画面は常時ボタンから開く全画面オーバーレイです。黒70%の半透明背景、見とるは赤 `#DC2626`、見とらんは緑 `#16A34A`、白太字の縦書きとし、山札区切り・通算番号・山札内番号を表示します。全件の時系列表示と縦スクロールに対応します。表示テーマと監視判定を分離しています。履歴画面表示中は背後の入力を抑制し、開閉処理自体はドロー・ターン進行・時間停止を行いません。

## 外部仕様の境界と未確定事項

- 視界判定は `IGuardVisionService`、脱獄失敗処理は `IGuardPrisonerService` に分離しました。
- 既定の `PrototypeGuardVisionService` は既存 `GridManager.IsProtected()`、`PrototypeGuardPrisonerService` は既存 `Prisoner.Capture()` を使う暫定アダプターです。SYS-VISION-001／SYS-PRISONER-001 の確定実装とは扱いません。
- 看守ターンの発生は既存ゲームフローを使用します。他行動・カードとの厳密な処理順、視界形状・反転、囚人の失敗後の状態遷移・特殊能力は別仕様待ちです。
- 監視演出・表示時間・スキップ・オンライン／オフライン進行制御は未確定です。履歴開閉による新しい進行ルールは追加していません。
- オンライン通信は未実装です。現在の公開履歴APIは秘密情報を含みませんが、将来のオンライン実装では監視山札を権威側だけに保持し、非公開情報をクライアントへ配信しない設計が別途必要です。
- 本番スキルカードと山札構成は未提供です。既定シーンの初期対局はスキルドローで仕様待ちになるため、本番の対局全体が完成したとは扱いません。監視検証用の明示的フィクスチャーは本番カードの代用ではありません。

## 実行済み検証

- Unity `6000.6.6f1` 同梱Roslynで、`unity-4.8-api` を参照してコンパイルし、同梱Monoで実行しました。Unity非依存の山札・公開履歴データと検証コードを対象とし、列挙型だけを独立runnerに定義しています。
